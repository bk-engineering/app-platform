# 0004 · modular monolith ไม่ใช่ microservices

<Status value="implemented" />

- **สถานะ:** accepted
- **วันที่:** 2026-08-02
- **หมวด:** backend

## บริบท

boilerplate นี้เป็นจุดเริ่มต้นของผลิตภัณฑ์ที่ยังไม่รู้ว่าจะโตไปทางไหน ทีมเล็ก ปริมาณโหลดยังไม่รู้ ขอบเขตของโดเมนยังไม่นิ่ง

## การตัดสินใจ

**หนึ่ง deployment ของ NestJS ที่แบ่งเป็นโมดูลอย่างเข้มงวด**

- หนึ่งโฟลเดอร์ = หนึ่งโมดูล = หนึ่ง bounded context (`auth`, `users`, …)
- โมดูลคุยกันผ่าน service ที่ export ออกมาเท่านั้น ห้ามเรียก repository ข้ามโมดูล
- ทุกโมดูลใช้ Postgres instance เดียวกัน แต่ **โมดูลอื่นห้ามแตะตารางที่ไม่ใช่ของตัวเอง** ผ่าน Prisma โดยตรง

## ทางเลือกที่พิจารณา

### Microservices ตั้งแต่วันแรก
ให้ขอบเขตที่ compiler บังคับได้จริงและ scale แต่ละส่วนแยกกันได้ แต่ต้องแบก service discovery, distributed transaction, การ debug ข้าม service, versioning ของ API ภายใน, และ observability ที่ซับซ้อนกว่ามาก — ทั้งหมดนี้เพื่อแก้ปัญหาที่เรายังไม่มี

ที่สำคัญกว่า: การแบ่ง service ผิดตั้งแต่แรกแก้ยากกว่าการแบ่งโมดูลผิดหลายเท่า และตอนที่ยังไม่รู้จักโดเมนดี โอกาสแบ่งผิดสูงมาก

### Monolith ที่ไม่มีขอบเขต
เร็วที่สุดในระยะสั้น แต่พอโค้ดโตแล้วจะแยกไม่ออกเลยว่าอะไรเป็นของใคร และการแตกออกทีหลังจะกลายเป็นงานรื้อทั้งระบบ

### Serverless functions
scale ตามโหลดได้ดีและไม่ต้องดูแล server แต่ cold start กระทบ latency, การเชื่อม DB ต้องมี pooler เพิ่ม, และการพัฒนาบนเครื่องยุ่งกว่า Docker Compose มาก

## ผลที่ตามมา

**ได้:** deploy ที่เดียว debug ที่เดียว · transaction ของฐานข้อมูลใช้ได้จริงข้ามโดเมน · refactor ขอบเขตได้ด้วยการย้ายไฟล์ ไม่ต้องแก้สัญญาระหว่าง service · เครื่องมือ dev บนเครื่องง่ายมาก

**เสีย:** scale แยกส่วนไม่ได้ · โมดูลที่ทำงานหนักกระทบทั้ง process · ขอบเขตถูกบังคับด้วยวินัยและ code review ไม่ใช่ compiler

**ต้องทำต่อ:** เพิ่ม eslint rule ห้าม import ข้ามโมดูลนอกจากผ่าน `index.ts` ของโมดูลนั้น เพื่อให้ขอบเขตถูกบังคับด้วยเครื่องมือ

## เมื่อไหร่ควรทบทวน

เมื่อโมดูลใดโมดูลหนึ่งมีรูปแบบการใช้ทรัพยากรที่ต่างจากที่เหลืออย่างชัดเจน (เช่น งานประมวลผลไฟล์ที่กิน CPU หนักและกระทบ latency ของ API) — ตอนนั้นแยก *โมดูลนั้นตัวเดียว* ออกมา ไม่ใช่แตกทั้งระบบ ขอบเขตที่รักษาไว้จะทำให้แยกได้โดยไม่ต้องรื้อ
