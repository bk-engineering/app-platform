## สถานะ

| สถานะ | หมายความว่า |
| --- | --- |
| `proposed` | เสนอแล้ว ยังไม่ตกลง |
| `accepted` | ตกลงแล้ว มีผลบังคับ |
| `superseded by ADR-XXXX` | ถูกแทนที่ ยังอ่านได้เพื่อรู้บริบทเดิม |
| `deprecated` | ไม่ใช้แล้ว แต่ไม่มีอะไรมาแทน |

::: danger ADR ที่ accepted แล้วห้ามแก้
ต้องการเปลี่ยนใจ = เขียน ADR ใหม่ที่ supersede ของเดิม แล้วอัปเดตสถานะของอันเก่าให้ชี้ไปหาอันใหม่ ADR คือบันทึกประวัติศาสตร์ ไม่ใช่เอกสารที่ยังมีชีวิต — คุณค่าทั้งหมดมาจากการอ่านย้อนได้ว่าตอนนั้นคิดยังไงและรู้อะไรบ้าง
:::

การแก้คำผิดหรือแก้ลิงก์เสียทำได้ ที่ห้ามคือแก้เนื้อหาของการตัดสินใจ

```md
## บริบท

ตอนตัดสินใจ สถานการณ์เป็นยังไง มีข้อจำกัดอะไร รู้อะไรและ*ไม่*รู้อะไร

## การตัดสินใจ

เลือกอะไร เขียนเป็นประโยคบอกเล่า ("เราจะ…")

## ทางเลือกที่พิจารณา

### ทางเลือก A — <ชื่อ>
ข้อดี · ข้อเสีย · ทำไมไม่เลือก

### ทางเลือก B — <ชื่อ>
ข้อดี · ข้อเสีย · ทำไมไม่เลือก

## ผลที่ตามมา

**ได้อะไร** · **เสียอะไร** · **ต้องทำอะไรต่อ**

## เมื่อไหร่ควรทบทวน

สัญญาณอะไรที่บอกว่าการตัดสินใจนี้ควรถูกพิจารณาใหม่
```

## เมื่อไหร่ต้องเขียน ADR

**ต้องเขียน** เมื่อการตัดสินใจนั้น กลับตัวยาก · มีผลข้ามหลาย workspace · เลือกระหว่างของที่ทำงานได้พอ ๆ กัน · หรือขัดกับสิ่งที่คนทั่วไปคาดหวัง

**ไม่ต้องเขียน** เมื่อเป็นการเลือกที่มีคำตอบชัดเจนอยู่แล้ว · เป็นเรื่องภายในไฟล์เดียว · หรือเป็นเรื่องรสนิยมที่ linter บังคับได้

ถ้าลังเล ให้ถามว่า *"อีกหกเดือนจะมีคนถามไหมว่าทำไมทำแบบนี้"* ถ้าใช่ ก็เขียน
